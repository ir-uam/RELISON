BoundaryNodes

Distinct members incident to at least one edge crossing the community boundary.

Direction and weights

Boundary metrics accept OUT, IN or UND. In directed graphs, these select outgoing connections, incoming connections, or both. Boundary-node and neighboring-community counts take unions for UND so a node or community is counted once. Undirected graphs ignore the orientation. MUTUAL is not supported.

The last four classes accept a weighted flag, defaulting to false. Weighted mode requires finite nonnegative weights and uses each parallel edge's own weight. Unweighted mode counts each physical edge, including parallel edges, once. Boundary-node and neighboring-community metrics are structural counts: zero-weight edges still establish a boundary connection.

For internal volume, an undirected internal edge contributes two incidences, including a loop. A directed internal edge contributes one in OUT/IN mode or two in UND mode. This is a ratio of aggregated volumes, not an average of node ratios.

Conductance uses T = V minus C. Its directed variants are explicitly defined as:

  • OUT: cut(C,T) / min(outVolume(C), inVolume(T)).
  • IN: cut(T,C) / min(inVolume(C), outVolume(T)).
  • UND: combined crossing mass / min(combined in/out volume(C), combined in/out volume(T)).

These directed variants are implementation conventions extending the symmetric undirected definition. They are documented explicitly in the class Javadoc. Expansion uses this community's size as its denominator, rather than the smaller of the two sides' sizes.

Internal-volume fraction and conductance return NaN for zero-volume denominators; expansion returns NaN for an empty community. In the GUI, undefined values become JSON nulls, display as a dash, are excluded from finite-value averages, and export as empty CSV cells. No undefined result is converted to zero.

ModularityContribution

Standard Newman modularity contribution, optionally weighted and with resolution gamma.

Direction and weights

Boundary metrics accept OUT, IN or UND. In directed graphs, these select outgoing connections, incoming connections, or both. Boundary-node and neighboring-community counts take unions for UND so a node or community is counted once. Undirected graphs ignore the orientation. MUTUAL is not supported.

In the GUI, undefined values become JSON nulls, display as a dash, are excluded from finite-value averages, and export as empty CSV cells. No undefined result is converted to zero.

Modularity contribution

Let m be total graph edge mass, L_C internal edge mass, and gamma the resolution. Undirected contribution is L_C/m - gamma*(volume(C)/(2m))^2. Directed contribution is L_C/m - gamma*(outVolume(C)/m)*(inVolume(C)/m). Each loop contributes once to L_C; undirected degree volume counts it twice. A complete node partition is required. Zero graph mass yields zero.

These contributions sum to standard Newman modularity. They do not sum to RELISON's existing differently normalized global communities.graph.Modularity score. The GUI identifies this metric as Modularity contribution (Newman).
